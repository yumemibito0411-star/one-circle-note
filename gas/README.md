# ONE CIRCLE 人脈ノートを新しいGoogleアカウントで作る

旧Apps Scriptは使わず、このフォルダーのサーバーで新しく動かします。データは自分のGoogleドライブ内のスプレッドシートに保存します。AI解析は「文字起こしを貼る → AIで解析 → 結果の確認 → 反映する」で使えます。確認画面の `previewHtml` / `applyAI` と「AI用にコピー」は維持しています。

最初に用意するものは、新しいGoogleアカウント、このリポジトリのファイル、必要に応じてAnthropic APIキーです。旧データを移す場合は、旧サーバーがまだ動いているうちに下の「データの引き継ぎ」でJSONを控えてください。

## 1. 新しいスプレッドシートとApps Scriptを作る

1. 新しいGoogleアカウントでGoogleドライブを開きます。
2. 「新規」→「Google スプレッドシート」→「空白のスプレッドシート」を選びます。
3. 名前を「ONE CIRCLE 人脈ノート」などに変更します。セルへの入力は不要です。
4. 上部の「拡張機能」→「Apps Script」を開き、プロジェクト名も分かる名前に変更します。

シートを他のメンバーに直接共有する必要はありません。アプリはデプロイしたGoogleアカウントの権限で読み書きします。

## 2. ファイルを貼り付ける

Apps Script編集画面で、次のようにファイルを用意します。

| リポジトリのファイル | Apps Scriptでの操作 |
| --- | --- |
| `gas/Code.gs` | 最初からある `Code.gs` の中身をすべて置き換える |
| `gas/ai.gs` | 「ファイル」の「＋」→「スクリプト」、名前を `ai` にして貼る |
| ルートの `index.html` | 「ファイル」の「＋」→「HTML」、名前を **`index`** にして中身をすべて貼る |
| `gas/appsscript.json` | 下記の方法で表示した `appsscript.json` の中身を置き換える |

`appsscript.json` は、左の歯車「プロジェクトの設定」から「『appsscript.json』マニフェスト ファイルをエディタで表示する」を有効にするとファイル一覧に出ます。ファイルをすべて保存してください。`tests/` のファイルはApps Scriptに貼りません。

この時点では、`index.html` の `API_URL` はまだ変更しません。GAS上で表示する画面は `google.script.run` を使うため、後述の新しいURLの設定前でも動きます。

## 3. setupを一度実行する

1. 編集画面上部の関数選択で `setup` を選び、「実行」を押します。
2. 初回はGoogleの承認画面が出ます。作成に使っているアカウントを選び、スプレッドシートへのアクセスと外部サービスへの接続を許可します。自作アプリの未確認表示が出た場合は、作成したプロジェクトであることを確認して進めます。組織の設定で承認できない場合は、そのアカウントの管理者に確認してください。
3. 実行ログに **「初期管理者キー（この実行時だけ表示）」** が出ます。この値を安全な場所に控えます。コードやGitHubに貼らないでください。
4. スプレッドシートに `members`・`people`・`logs`・`handoffs`・`config` の5シートができていることを確認します。最初の空シートは残っていて構いません。

`setup()` は、このスプレッドシートのIDをスクリプトプロパティ `DB_ID` に自動保存し、最初の管理者を作ります。スプレッドシートと紐付いていないスクリプトから実行した場合は、新しいスプレッドシート自体も自動作成します。再実行しても既存のデータ・キーは変えず、キーも再表示しません。初期設定を済ませてから公開してください。

## 4. AIのキーを登録する（任意）

1. Apps Scriptの歯車「プロジェクトの設定」を開きます。
2. 「スクリプト プロパティ」→「スクリプト プロパティを追加」を選びます。
3. プロパティ名を `ANTHROPIC_API_KEY` とし、値の欄に利用するAnthropic APIキーを入力して保存します。APIの利用には利用可能な残高・利用枠が必要です。
4. 必要なら `AI_MODEL` も追加し、そのキーで利用できるモデルIDを設定します。未設定・空欄の場合は依頼仕様どおり `claude-sonnet-5-5` を使います。このモデルIDを利用できない場合は、利用可能なIDに変更してください。

`DB_ID` はsetupが登録済みなので変更しません。APIキーは設定画面だけに保存し、コード・README・PRには書きません。AIキーを登録しなくてもノートは利用でき、「AI用にコピー」と手動JSON読み込みを使えます。キーの有効性・モデルの利用可否は解析実行時に確認されます。

## 5. ウェブアプリとしてデプロイする

1. 右上の「デプロイ」→「新しいデプロイ」を選びます。
2. 種類の歯車から「ウェブアプリ」を選びます。
3. 説明を入力し、「次のユーザーとして実行」は **自分（デプロイするアカウント）** にします。
4. 「アクセスできるユーザー」は **全員** にします。Googleログインを求める「Googleアカウントを持つ全員」ではなく、ログインなしの全員です。アプリ内では個人キーで認証します。
5. 「デプロイ」を押します。必要に応じて承認します。
6. 表示された **ウェブアプリURL（末尾が `/exec`）** を控えます。テスト用の `/dev` URLは使いません。
7. このURLの末尾に、半角の `?`、`k`、`=`、手順3の管理者キーを順に付けてブラウザーで開きます。これが最初の管理者の個人URLです。個人URLは認証情報なので、本人以外に渡したりリポジトリへ保存したりしないでください。

個人URLなしで開くと「このリンクでは開けません」と表示されます。管理者の画面で「あなたの名前」を変更できます。メンバー一覧に表示する初期管理者名は「最初の管理者」です。

マニフェストは `Asia/Tokyo`、V8、`executeAs: USER_DEPLOYING`、`access: ANYONE_ANONYMOUS` に設定済みです。スコープはスプレッドシートの読み書きと外部HTTP通信です。デプロイ画面でも上の実行者・公開範囲を確認してください。

## 6. 外部ページ用のAPI_URLを新しいURLにする

このPRでは、まだ決まっていない新しいURLへの置き換えを行っていません。リポジトリの既存 `API_URL` は維持しています。

1. 新しいデプロイURLが決まったら、ルートの `index.html` をテキストエディターで開き、`const API_URL` を検索します。
2. 既存の `"https:" + SL2 + "script.google.com/macros/s/…/exec"` という形式を維持し、デプロイID部分（`/s/` と `/exec` の間）を新しいものに置き換えます。`SL2` は2つのスラッシュを組み立てる既存の定数です。
3. 設定するのは全員共通のウェブアプリURLだけです。個人キーや認証パラメーターを `API_URL` に付けないでください。
4. 外部で配信しているHTMLも、この `index.html` に更新します。外部ページを個人URLで開く場合も、新しいサーバーが発行したキーを使います。
5. Apps ScriptのHTMLファイル `index` にも更新した内容を貼り、保存します。
6. 「デプロイ」→「デプロイを管理」→現在のデプロイ→鉛筆（編集）→バージョン **「新しいバージョン」** →「デプロイ」で更新します。同じデプロイを編集すればURLは変わりません。

今後 `Code.gs`・`ai.gs`・`index` を変更したときも、保存後に「新しいバージョン」で更新してください。新しいGoogleアカウントで作った管理者・メンバーのURLへ切り替えます。旧キーは新サーバーで使えません。

## 7. データの引き継ぎ

### 旧データのJSONを用意する

すでに旧 `bootstrap` のJSONがあれば、そのまま使えます。データ部分だけでも、APIの `{ok:true,data:...}` 全体でも取り込めます。

旧画面をまだ開ける場合、次の方法でも控えられます。

1. **旧サーバーを使っている画面**で、移したい本人のノートを開き「最新にする」を押します。
2. ブラウザーの開発者ツール（Chromeならメニュー→その他のツール→デベロッパーツール）を開き、「Console」を選びます。Apps Script内の画面では、実行コンテキストをアプリのフレーム（`call` 関数があるフレーム）に切り替える必要があります。難しい場合は、この操作だけ分かる方に依頼してください。
3. 以下の内容を確認して実行します。自分のノートのデータだけをクリップボードへコピーします。キーやメンバー一覧は含めません。

```javascript
const migrationData = await call("bootstrap", {});
copy(JSON.stringify({
  people: migrationData.people,
  logs: migrationData.logs,
  handoffs: migrationData.handoffs,
  global: migrationData.global,
  mine: migrationData.mine
}, null, 2));
```

他の人のデータは、その人の旧URLで同じ操作をするか、リーダー／管理者が `call("bootstrap", {view: "旧メンバーのID"})` で取得します。画面で閲覧先を変えても、上の空の `{}` は認証した本人を取得するため、他の人を移すときは必ず `view` を指定してください。旧サーバー自体に接続できない場合、この仕組みで過去データを取り出すことはできません。手元のJSONバックアップが必要です。

### 新しい画面で取り込む

1. 新サーバーの管理者の個人URLで開き、「メンバー管理」へ進みます。
2. 他の人のデータを移す場合は、先に「メンバーを追加」でその人を登録します。
3. **「データを取り込む（JSONを貼り付け）」** を開き、取り込み先メンバーを選びます。既定は管理者本人です。
4. JSONを貼り、「取り込む（同じIDは上書き）」を押します。件数が表示されたら、チーム画面から取り込み先のノートを閲覧して確認します。
5. 管理者は、新しい個人URLを「メンバー一覧」からコピーして本人に渡します。

取り込み時の動作は次のとおりです。

- `people`・`logs`・`handoffs` は、選択したメンバーのデータとして保存します。同じメンバー内で同じ `id` があればレコード全体を上書きします。他メンバーの同じIDには影響しません。JSONにない既存レコードは削除しません。
- `mine`（個人名・目標・テーマ・相談事項）は取り込み先へ、`global`（事業・面談の種類・文面書式）は全員共通へ反映します。設定は項目単位で再帰的にマージし、配列は置き換えます。共通設定を移したくない回は、JSONから `global` 項目を外してください。
- `me`・`target`・`members`・`ai` は無視します。旧キー、旧管理者権限、旧DB設定は取り込みません。
- 1回につき1人のbootstrapデータを取り込みます。旧メンバーと新メンバーのIDが異なっても、人物・記録・つなぎ依頼のIDと参照関係は維持します。
- 不正な形式、参照先の人物がない記録、許可外の設定項目は拒否します。IDは英数字・ハイフン・アンダースコア、1〜160文字です。1レコードの保存JSONは45,000文字以内、API入力JSONは5,000,000文字以内です。大きなバックアップは人物を先に、記録・依頼を後に分割して取り込めます。

取り込み前にスプレッドシートをコピーして控えておくと、上書き前の状態を残せます。入力検証は書き込み前に完了しますが、Google Sheetsは複数シートをまとめたトランザクションを提供しないため、書き込み途中のサービス障害で一部だけ反映される可能性があります。同じJSONを再実行すると同じIDを上書きします。

## 8. 動作を確認する

1. 人物を1人追加し、「最新にする」後も残ることを確認します。面談の記録・つなぎ依頼・目標も同様に確認します。
2. メンバーを追加し、新しい個人URLで自分のノートだけを開けることを確認します。リーダーはチーム全員を閲覧でき、他人のノートは編集できません。管理者はメンバー管理と共通設定も操作できます。
3. メンバーの停止で個人URLが無効になり、再開で再び使えること、URL再発行で古いキーが無効になることを確認します。自分自身の停止・降格はできません。自分のURL再発行では画面の認証情報も更新します。表示される新しい個人URLを控え直してください。
4. AIキーを設定した場合、「AIで解析」が出ることを確認します。個人情報のない短い文字起こしで、解析結果の確認→必要な項目だけ選択→「反映する」を試します。「破棄」でも終了できます。解析前に自動保存はしません。
5. 「AI用にコピー」も残っていることを確認します。AIキーを削除して再読み込みすると手動利用に戻ります。

AI解析では、プロンプトに含まれる文字起こし・既存の人物情報・事業情報をAnthropicへ送信します。通常のAPI呼び出しはキー・入力・レスポンス全文をログに出しません。例外として、初回のsetupだけは依頼どおり初期管理者キーを実行ログへ一度表示します。シートの `members` には再配布用のキーが保存されるため、スプレッドシートとApps Scriptの編集権限は管理者だけが持つようにしてください。

## 困ったとき

| コード／表示 | 確認すること |
| --- | --- |
| `invalid_key`／このリンクでは開けません | 新しい個人URLか、メンバーが停止中でないか、キー再発行前のURLでないか |
| `not_setup` | `setup` を実行したか、`DB_ID` を変えていないか |
| `forbidden` | 操作に必要な管理者・リーダー権限があるか |
| `self_admin` | 自分自身を停止・降格しようとしていないか |
| `invalid_payload` | JSONの形、ID、容量、設定項目、記録の人物IDが正しいか |
| `not_found` | 指定メンバーや自分のノート内の参照先人物が存在するか |
| `busy` | 他の保存が実行中。少し待って再実行する |
| `server_error` | 保存先シートのアクセス権・列名・データ形式、Google側のサービス状態を確認する |
| `no_key` | スクリプトプロパティ `ANTHROPIC_API_KEY` を設定したか |
| `rate_limited` | Anthropic側のHTTP 429／529。少し待って再実行する |
| `refused` | AIが回答を控えた。文面を見直すか手動入力する |
| `too_long` | 送信プロンプト全体が80,000字相当を超過。短くして分ける |
| `ai_error` | APIキー・モデル・利用枠・通信を確認する。出力途中終了や不正応答も含む |
| `invalid_json` | フロント側でAIの返答をJSONとして読めない。再解析するか入力を短くする |

既存画面は文字起こしを先頭60,000文字までプロンプトに含める仕様です。サーバーは既存情報も含むプロンプト全体をJavaScriptの文字列長で判定します。AI出力は最大8,192トークンで、途中終了は `ai_error` にします。

## API仕様（保守する方向け）

3入口は同じ `api()` の認証・振り分け・エラー変換を通ります。

- `doGet(e)`：認証を確認し、HTMLファイル `index` の `__BOOT__` を安全にエスケープしたJSONで置換します。BOOTは画面が使う `{key,url,external:false}` です。無効キーでもHTMLを返し、画面がエラー案内を表示します。
- `doPost(e)`：`text/plain` のJSON `{key,action,payload}` を受け、JSONレスポンスを返します。
- `api(key,action,payloadJson)`：`google.script.run` 用。第3引数はJSON文字列で、返り値もJSON文字列です。

レスポンスは `{ok:true,data:...}` または `{ok:false,error:"コード"}`。以下の表の入力は `payload`、出力は成功時の `data` です。本人は認証キーで決め、保存APIに他人の所有者IDを指定しても保存先は変わりません。他人の閲覧は `bootstrap.view` のみです。

| アクション | 入力 | 出力・権限 |
| --- | --- | --- |
| `bootstrap` | `{view?: memberId}` | `{me,target,members,people,logs,handoffs,global,mine,ai}`。他人のviewはリーダー／管理者のみ。me/targetはキーなし。membersは管理者だけ全員分（配布用キー含む）、他は空配列 |
| `savePerson` | `{person:{id,...}}` | 本人の人物を全体置換して返す |
| `deletePerson` | `{id}` | `null`。本人の人物と関連logs/handoffsを削除 |
| `addLog` | `{log:{id,personId,type,date,createdAt?,text?,biz?,...}}` | 本人の人物に紐付くlogを保存して返す。ID・日時は画面が生成 |
| `deleteLog` | `{id}` | `null`。本人の記録だけ削除 |
| `saveHandoff` | `{handoff:{id,personId,...}}` | 本人の人物に紐付くhandoffを保存して返す |
| `deleteHandoff` | `{id}` | `null`。本人の依頼だけ削除 |
| `saveGlobal` | `{patch:{businesses?,kinds?,lineTemplate?}}` | マージ後のglobal。管理者のみ |
| `saveMine` | `{patch:{me?,goals?,themes?,shareAsk?}}` | マージ後の本人のmine |
| `addMember` | `{name,role?:"member"\|"leader"\|"admin"}` | 新しい `{id,name,role,active,key}`。管理者のみ |
| `updateMember` | `{id,role?,active?,newKey?:true}` | 更新後の同じメンバー形式。管理者のみ。自分の停止・降格はself_admin |
| `teamSummary` | `{}` | 有効メンバーの `{id,name,role,counts,goals,theme,list,late,back,last}[]`。リーダー／管理者のみ。countsは当月のcontact/meeting/propose/connect/won/new、goals/themeは当月、listは人物数、lateは未完了で期限を過ぎたアクション数、backは画面のhoBacklogと同条件の件数、lastは最終記録日。日付は日本時間 |
| `ai` | `{prompt}` | `ai.gs` の `aiAction_()` が返すテキスト文字列。有効メンバー全員 |
| `importData` | `{memberId?:新メンバーID,data:旧bootstrap}` または旧bootstrapそのもの | `{memberId,counts:{people,logs,handoffs}}`。管理者のみ。memberId省略時は本人 |

シートはヘッダー `id` / `json`、1行1レコードです。`members` はメンバーIDとメンバーJSON、`people`・`logs`・`handoffs` は「メンバーID:レコードID」と `{ownerId,record}`、`config` は `global` または `mine:メンバーID` と設定JSONです。全データ操作を `LockService.getScriptLock()` で排他し、AI外部通信前にはロックを解放します。スプレッドシートを直接編集する操作はこの排他の対象外です。

## 開発時の確認

Node.jsがある環境で、リポジトリのルートから実行できます。実際のGoogle・Anthropicサービスには接続せず、モックで認証・権限・所有者分離・全CRUD・取り込み・入口・AIの未設定時などを確認します。

```sh
node --test tests/gas.test.cjs
node --check < gas/Code.gs
node --check < gas/ai.gs
```

本番のGoogleアカウントでの承認、デプロイ、外部ページの通信、実AI解析は上記の手動手順で確認してください。
