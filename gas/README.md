# 文字起こしのAI解析を有効にする手順

このフォルダーの `ai.gs` は、既存のGoogle Apps Scriptに追加する部品です。このリポジトリにはサーバー本体の `Code.gs` がないため、ファイルを追加するだけでは有効になりません。以下の組み込みと再デプロイが必要です。

設定後は「文字起こしを貼る → AIで解析 → 解析結果の確認 → 反映する」で使えます。既存の `previewHtml` / `applyAI` はそのまま使い、チェックした項目を確認後に反映します。「AI用にコピー」と手動のJSON読み込みも引き続き使えます。

## 1. Apps Scriptにファイルを追加する

1. 現在このアプリで使っているApps Scriptの編集画面を開きます。別のプロジェクトを新規作成せず、既存の `Code.gs` があるものを使ってください。
2. 変更前の `Code.gs` を手元に控えておきます。
3. 左側の「ファイル」の「＋」から「スクリプト」を選び、名前を `ai` にします（画面上では `ai.gs` になります）。
4. このフォルダーの `ai.gs` の内容をすべて貼り付け、保存します。

## 2. 既存のCode.gsにつなぐ

以下は組み込み例です。既存の変数名・返却用関数に合わせて調整してください。`Code.gs` 全体をこの例で置き換えないでください。

### APIの振り分けに「ai」を追加する

`api` 関数などで `action` ごとに処理を選んでいる `switch` を探します。**既存のキー認証・アクセス権の確認を通った後**の振り分けに追加してください。`payload` は既存処理と同様にJSONを解析済みのオブジェクトを渡します。

```javascript
case "ai":
  data = aiAction_(payload);
  break;
```

これは共通の変数 `data` に結果を入れ、switchの後で成功レスポンスを返す構成の例です。既存の分岐がその場でreturnする形なら、その書き方に合わせます。成功レスポンスは、必ず次の形にしてください。`data` はJSONオブジェクトではなく、AIから返った**テキスト文字列**です。フロント側の `makeAI()` が文字列からJSONを取り出します。

```javascript
return JSON.stringify({ ok: true, data: data });
```

### エラーはコードだけを返す

`aiAction_()` は失敗時に `new Error("no_key")` などをthrowします。既存APIのcatch処理で `error.message` を読み、`{ok:false,error:"コード"}` として返す必要があります。既存処理が `error.code` を使っている場合も、この分岐からの例外を扱えるようにしてください。例えば既存のcatch内に次の変換を追加します。

```javascript
var aiCodes = ["no_key", "rate_limited", "refused", "too_long", "ai_error"];
if (action === "ai") {
  var code = error && error.message;
  return JSON.stringify({
    ok: false,
    error: aiCodes.indexOf(code) !== -1 ? code : "ai_error"
  });
}
// 他のアクションの既存エラー処理をこの後に残します。
```

catchの変数名が `e` なら、例の `error` を `e` に読み替えてください。HTTPの `doPost` が `ContentService` で返す構成なら、その既存の返却方法を使って同じJSON形式を返します。ブラウザーからのHTTP経由と `google.script.run.api` 経由の両方で、同じ認証・分岐・エラー変換を通すようにします。

既存APIに入力や例外のログ出力がある場合、`ai` アクションの入力・APIキー・レスポンス全文をログに記録しないようにしてください。`ai.gs` 自体はログを出しません。

### bootstrapの返り値にaiを追加する

起動時の `bootstrap` 処理で返しているデータオブジェクトに、次の項目を追加します。すでに `ai: false` があれば置き換えます。他の項目は残してください。

```javascript
ai: aiEnabled_()
```

APIの外側の `{ok:true,data:...}` ではなく、`me`・`people` などが入っている内側のデータに追加します。返すのは有効・無効の真偽値だけです。APIキーそのものは返さないでください。

## 3. スクリプトプロパティを登録する

1. Apps Script左側の歯車アイコン「プロジェクトの設定」を開きます。
2. 「スクリプト プロパティ」で「スクリプト プロパティを追加」を選びます。
3. プロパティ名を `ANTHROPIC_API_KEY` にし、「値」に利用するAnthropicのAPIキーを入力して保存します。APIの利用には利用可能な残高・利用枠が必要です。
4. 必要な場合だけ、プロパティ名 `AI_MODEL` を追加し、そのAPIキーで利用できるモデルIDを値に指定します。未設定または空欄の場合は、依頼仕様どおり `claude-sonnet-5-5` を使います。モデルが利用できない場合は、利用可能なモデルIDに設定してください。

キーはこの設定画面だけに保存します。`index.html`、`ai.gs`、Gitの設定、README、PRには書かないでください。個人用のアクセスURLやその認証パラメーターも転記しないでください。

`aiEnabled_()` はキーが空でないかだけを判定します。キーやモデルが実際に利用可能かは、解析を実行したときに確認されます。キーを削除してアプリを再読み込みすると、「AI用にコピー」による手動利用に戻せます。

## 4. ウェブアプリを「新しいバージョン」で再デプロイする

1. Apps Scriptの変更をすべて保存します。
2. 右上の「デプロイ」→「デプロイを管理」を開きます。
3. 現在使っているウェブアプリのデプロイを選び、鉛筆アイコン（編集）を押します。
4. 「バージョン」で **「新しいバージョン」** を選びます。説明には「文字起こしAI解析を追加」などと入力します。
5. 実行ユーザーとアクセス範囲は既存設定を維持し、「デプロイ」を押します。外部通信の承認を求められた場合は内容を確認して承認します。
6. 同じデプロイの更新なので、既存のウェブアプリURLをそのまま利用します。アプリを再読み込みしてください。保存だけでは公開中のコードは更新されません。

外部ページとして配信している `index.html` も、この変更版に更新してください。これはGASの再デプロイとは別の作業です。Apps ScriptのマニフェストでOAuthスコープを明示している場合は、既存スコープを維持したうえで `https://www.googleapis.com/auth/script.external_request` が必要です。通常の自動検出では追加操作は不要です。

## 5. 動作を確認する

1. アプリを再読み込みし、人物の「文字起こしから更新」に「AIで解析」が表示されることを確認します。
2. 個人情報を含まない短いテスト用の文字起こしを貼り、「AIで解析」を押します。解析用プロンプトに含まれる文字起こし・既存情報・事業情報はAnthropic APIへ送信されます。
3. 「解析結果の確認」が表示され、反映ボタンを押すまでは保存されないことを確認します。「破棄」で終了することもできます。
4. テスト用の人物で必要な項目だけチェックし、「反映する」で保存されることを確認します。
5. 「AI用にコピー」と手動読み込みも利用できることを確認します。

| コード | 意味・対応 |
| --- | --- |
| `no_key` | キーが未登録。スクリプトプロパティを確認します。 |
| `rate_limited` | HTTP 429 / 529。時間を置いて再実行します。 |
| `refused` | APIの `stop_reason` が `refusal`。文面を見直すか、手動で入力します。 |
| `too_long` | APIへ渡すプロンプトが80,000字相当（JavaScriptの文字列長）を超過。入力を短くします。 |
| `ai_error` | 通信失敗、無効なキー・モデル、想定外の応答、出力の途中終了など。設定を確認して再実行します。 |
| `invalid_json` | フロント側で返答をJSONとして読めなかった場合。再実行するか入力を短くします。 |

長さの制限は文字起こし単体ではなく、既存情報などを含めた送信プロンプト全体に適用します。既存画面は文字起こしを先頭60,000字までプロンプトに含める仕様のままです。AIの返答は最大8,192トークンとし、途中で出力が切れた場合は `ai_error` にします。
